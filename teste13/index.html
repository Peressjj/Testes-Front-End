Principais animações CSS

Cada card abaixo tem a animação rodando, a explicação de para que ela serve e o CSS que a cria. Todo o código está em style.css, comentado por seção.

transition — do estado A para o B

Suaviza a mudança de uma propriedade quando algo acontece: passar o mouse, focar, clicar. Precisa de um gatilho, tem só início e fim, e não repete sozinha.

@keyframes + animation — vários estágios

Você descreve o que acontece em cada ponto do tempo (0%, 50%, 100%). Roda sozinha ao carregar a página, pode repetir infinitamente, inverter e ser pausada.

1. Transições — a base de tudo

Antes de usar @keyframes, entenda transition: a maior parte das interações de uma interface (botões, links, cards) é só isso.

Passe o mouse

transition no hover

Para que serve: fazer a mudança de cor, tamanho ou posição acontecer gradualmente em vez de "pular" de um estado para o outro.

Quando usar: praticamente em todo botão, link e card clicável. É o efeito que faz a interface parecer polida. 

.transicao-basica {
  background-color: var(--cor-destaque);
  /* propriedade | duração | aceleração */
  transition: background-color 0.4s ease,
              transform 0.4s ease;
}

.transicao-basica:hover {
  background-color: var(--cor-ok);
  transform: translateY(-10px);
}

A transition fica no estado normal, não no :hover. Assim o efeito é suave na ida e na volta.

Funções de tempo (timing functions) — passe o mouse neste card

Para que serve: controlar o ritmo do movimento. Todas as bolinhas percorrem a mesma distância no mesmo tempo (1,2s), mas com acelerações diferentes. É o que separa uma animação "robótica" de uma natural.

Quando usar cada uma: linear para giros e loaders (velocidade constante); ease-out para coisas que entram na tela (chega rápido e freia); ease-in para coisas que saem; ease-in-out para movimentos de ida e volta; cubic-bezier() quando quiser um exagero proposital — o valor abaixo passa do alvo e volta, criando o efeito de "elástico". 

.bolinha {
  transition-property: transform;
  transition-duration: 1.2s;
}

.tempo-linear      { transition-timing-function: linear; }
.tempo-ease        { transition-timing-function: ease; }
.tempo-ease-in     { transition-timing-function: ease-in; }
.tempo-ease-out    { transition-timing-function: ease-out; }
.tempo-ease-in-out { transition-timing-function: ease-in-out; }
.tempo-bezier      {
  transition-timing-function: cubic-bezier(0.68, -0.55, 0.27, 1.55);
}

/* o gatilho: passar o mouse no card move todas as bolinhas de uma vez */
.exemplo-tempos:hover .bolinha {
  transform: translateX(calc(100cqw - 100%));
}

transform: mover, redimensionar, girar e inclinar

Para que serve: mudar a aparência de um elemento sem mexer no layout da página. translate move, scale aumenta/diminui, rotate gira, skew inclina.

Quando usar: sempre que for animar posição ou tamanho. 

.exemplo-transform .caixa {
  transition: transform 0.5s ease;
}

.t-translate:hover { transform: translate(0, -20px); }
.t-scale:hover     { transform: scale(1.3); }
.t-rotate:hover    { transform: rotate(45deg); }
.t-skew:hover      { transform: skewX(-15deg); }

Regra de ouro de performance: anime só transform e opacity. Animar width, height, top ou margin obriga o navegador a recalcular o layout a cada quadro e trava em celulares.

2. Animações com @keyframes

Aqui você descreve estágios. Com from/to (só dois estados) ou com percentuais (0%, 50%, 100%) para quantos estágios quiser.

Eu apareci

Fade in

Para que serve: trazer um elemento da invisibilidade (opacity: 0) até ficar visível, em vez de ele simplesmente surgir.

Quando usar: entrada de conteúdo ao carregar a página, abertura de modais, imagens que terminaram de carregar, troca de abas. 

@keyframes aparecer {
  from { opacity: 0; }
  to   { opacity: 1; }
}

.fade-in {
  opacity: 0;                              /* estado inicial */
  animation: aparecer 1.2s ease forwards;  /* forwards = fica no estado final */
}

Sem forwards o elemento volta a ficar invisível ao terminar, porque a animação deixa de valer e o opacity: 0 da classe assume.

Deslizei

Slide in

Para que serve: fazer o elemento entrar deslizando de fora da área visível até a posição final, combinando translateX com opacity.

Quando usar: menu lateral (drawer), notificações (toast) que entram pelo canto, carrosséis, seções que aparecem conforme o usuário rola a página. 

@keyframes entrar-esquerda {
  from { opacity: 0; transform: translateX(-120px); }
  to   { opacity: 1; transform: translateX(0); }
}

.slide-in {
  opacity: 0;
  animation: entrar-esquerda 1s ease-out forwards;
}

Bounce (quicar)

Para que serve: dar a sensação de peso e elasticidade. O elemento sobe, cai, e quica cada vez com menos força — por isso os percentuais vão ficando mais próximos no fim.

Quando usar: chamar atenção para uma ação disponível (seta "role para baixo", ícone de chat, botão de ajuda). Use com parcimônia: movimento constante cansa. 

@keyframes quicar {
  0%   { transform: translateY(0); }
  30%  { transform: translateY(-30px); }
  50%  { transform: translateY(0); }
  70%  { transform: translateY(-15px); }  /* quica menos */
  85%  { transform: translateY(0); }
  92%  { transform: translateY(-6px); }   /* e menos ainda */
  100% { transform: translateY(0); }
}

.quicar:hover { animation: quicar 1.4s ease; }
3 novas

Pulse (pulsar)

Para que serve: crescer e voltar ao tamanho original. Serve para duas coisas: feedback (o botão responde ao clique) e destaque (algo pulsando em loop pede atenção).

Quando usar: feedback de clique em botões (uma vez só) e badges de notificação, botão de gravar, indicador "ao vivo" (em loop). 

@keyframes pulsar {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.12); }
  100% { transform: scale(1); }
}

/* uma vez, no clique */
.pulsar-clique:active { animation: pulsar 0.5s ease; }

/* em loop, para chamar atenção */
.badge { animation: pulsar 1.5s ease-in-out infinite; }

Shake (tremer) — clique dentro do campo

Para que serve: balançar o elemento rapidamente para os lados. É o gesto universal de "não" — comunica erro antes mesmo de a pessoa ler a mensagem.

Quando usar: erro de validação de formulário, senha incorreta, ação bloqueada. Sempre acompanhado de um texto explicando o erro — a animação sozinha não é acessível. 

@keyframes tremer {
  0%, 100% { transform: translateX(0); }
  20%, 60% { transform: translateX(-10px); }
  40%, 80% { transform: translateX(10px); }
}

.campo-erro:focus { animation: tremer 0.5s ease; }

Repare na vírgula: 20%, 60% aplica o mesmo estado a dois momentos diferentes, evitando repetir código.

Spinner (carregando)

Para que serve: girar 360° infinitamente. O truque: um quadrado com border-radius: 50% vira círculo, e só a borda de cima recebe cor — é essa diferença que deixa o giro visível.

Quando usar: espera sem progresso conhecido (requisição à API, upload sem percentual). Se você sabe quanto falta, prefira a barra de progresso. 

@keyframes girar {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}

.spinner {
  width: 54px;
  height: 54px;
  border: 6px solid #e0e0ec;
  border-top-color: var(--cor-destaque);  /* só o topo colorido */
  border-radius: 50%;
  animation: girar 0.9s linear infinite;  /* linear: giro sem solavanco */
}

Skeleton / shimmer

Para que serve: mostrar o "esqueleto" do conteúdo enquanto ele carrega. O brilho que atravessa é um degradê largo (background-size: 200%) cuja posição é animada.

Quando usar: listas, feeds e cards vindos de uma API. Melhor que o spinner porque já mostra o formato do que vai aparecer, e evita o layout "pular" quando os dados chegam. 

@keyframes brilho {
  from { background-position: -200% 0; }
  to   { background-position: 200% 0; }
}

.linha-fake {
  height: 14px;
  border-radius: 6px;
  background: linear-gradient(90deg, #e4e4ee 25%, #f4f4fa 50%, #e4e4ee 75%);
  background-size: 200% 100%;
  animation: brilho 1.4s linear infinite;
}
Olá, mundo!

Efeito de digitação

Para que serve: revelar o texto letra por letra. A largura cresce de 0 até 11ch (11 caracteres) e steps(11) faz isso em 11 saltos em vez de continuamente — é o que dá a sensação de teclado. Uma segunda animação pisca a borda da direita, que faz as vezes de cursor.

Quando usar: título de hero em portfólio, terminal falso, landing page de produto técnico. 

@keyframes digitar {
  from { width: 0; }
  to   { width: 11ch; }  /* 11 = nº de caracteres do texto */
}

@keyframes piscar {
  0%, 49%   { border-right-color: var(--cor-destaque); }
  50%, 100% { border-right-color: transparent; }
}

.digitando {
  white-space: nowrap;
  overflow: hidden;
  border-right: 3px solid var(--cor-destaque);
  /* duas animações no mesmo elemento, separadas por vírgula */
  animation: digitar 2.5s steps(11) infinite alternate,
             piscar 0.8s step-end infinite;
}

Gradiente animado

Para que serve: dar movimento a um fundo sem mexer em nada do layout. O degradê é feito 3x maior que o elemento (background-size: 300%) e o que se anima é a background-position.

Quando usar: botão de chamada principal (CTA), fundo de seção hero, cartões de destaque. 

@keyframes mover-gradiente {
  0%   { background-position: 0% 50%; }
  50%  { background-position: 100% 50%; }
  100% { background-position: 0% 50%; }
}

.gradiente {
  background: linear-gradient(90deg, #5b4bdb, #e11d48,
                              #f0b429, #16a34a, #5b4bdb);
  background-size: 300% 100%;
  animation: mover-gradiente 6s ease infinite;
}

Flip / card 3D

Para que serve: virar um card no espaço. Três propriedades fazem a mágica: perspective (profundidade) no pai, transform-style: preserve-3d (os filhos existem em 3D) e backface-visibility: hidden (esconde o lado que está de costas).

Quando usar: jogo da memória, flashcards de estudo, card de produto que revela detalhes no verso. 

.cena  { perspective: 800px; }

.carta {
  position: relative;
  transform-style: preserve-3d;
  transition: transform 0.7s ease;
}

.cena:hover .carta { transform: rotateY(180deg); }

.face  { position: absolute; inset: 0; backface-visibility: hidden; }
.verso { transform: rotateY(180deg); }

Barra de progresso

Para que serve: mostrar o avanço de algo. A barra interna cresce de 0% a 100% de largura, e o pai tem overflow: hidden com borda arredondada para o preenchimento respeitar o formato.

Quando usar: upload com percentual, progresso de um formulário em etapas, tempo restante de um toast. 

@keyframes preencher {
  from { width: 0%; }
  to   { width: 100%; }
}

.barra { overflow: hidden; border-radius: 999px; }

.preenchimento {
  width: 0;
  animation: preencher 4s ease-in-out infinite;
}

Aqui animamos width de propósito, porque é exatamente a largura que precisa mudar. Na prática, numa barra real, o valor vem do JavaScript.

Accordion (abrir e fechar)

Para que serve: revelar conteúdo escondido com transição. O detalhe importante: não é possível animar height: auto — o navegador não sabe de que número até que número ir. A solução clássica é animar max-height de 0 até um valor maior que o conteúdo.

Quando usar: FAQ, menus de navegação em celular, filtros que ocupam muito espaço. 

.acordeao .conteudo {
  max-height: 0;              /* fechado */
  overflow: hidden;
  padding: 0 16px;
  transition: max-height 0.5s ease, padding 0.5s ease;
}

.acordeao:hover .conteudo,
.acordeao:focus-within .conteudo {
  max-height: 200px;          /* qualquer valor maior que o conteúdo */
  padding: 12px 16px;
}

Se o max-height for muito maior que o conteúdo real, o fechamento parece ter um atraso — parte do tempo é gasta percorrendo espaço vazio.

3. As propriedades animation-*

O @keyframes diz o que acontece. Estas propriedades dizem como acontece.

0.6s
duration curta
3s
duration longa
∞
iteration-count: infinite
↔
direction: alternate
some
sem fill-mode
fica
com forwards
hover
play-state: paused

Para que serve cada propriedade

animation-name — qual @keyframes usar.
animation-duration — quanto tempo dura um ciclo. Interface normalmente fica entre 0.2s e 0.5s; acima de 1s parece lento.
animation-timing-function — o ritmo (ease, linear, steps()…).
animation-delay — espera antes de começar. Com valores diferentes por item, cria o efeito cascata.
animation-iteration-count — quantas vezes repete (um número ou infinite).
animation-direction — normal, reverse, alternate (vai e volta) ou alternate-reverse.
animation-fill-mode — o que vale fora da animação. forwards mantém o estado final; backwards aplica o inicial já durante o delay; both faz os dois.
animation-play-state — running ou paused. Passe o mouse na última caixa: ela congela. 

/* forma longa */
.caixa {
  animation-name: girar;
  animation-duration: 2s;
  animation-timing-function: linear;
  animation-delay: 0.3s;
  animation-iteration-count: infinite;
  animation-direction: alternate;
  animation-fill-mode: forwards;
}

/* forma abreviada — mesma coisa, nesta ordem:
   name duration timing-function delay iteration-count direction fill-mode */
.caixa {
  animation: girar 2s linear 0.3s infinite alternate forwards;
}

/* pausar no hover */
.pausavel:hover { animation-play-state: paused; }

Na forma abreviada, o primeiro valor de tempo é a duração e o segundo é o delay. animation: girar 2s 1s = dura 2s e espera 1s para começar.

  • Item 1 — delay 0.10s
  • Item 2 — delay 0.25s
  • Item 3 — delay 0.40s
  • Item 4 — delay 0.55s

Delay escalonado (efeito cascata)

Para que serve: em vez de a lista inteira aparecer de uma vez, cada item entra um pouquinho depois do anterior. É a mesma animação em todos, só o animation-delay muda — e o :nth-child() faz isso sem precisar de classe por item.

Quando usar: resultados de busca, itens de menu abrindo, cards de uma galeria. Mantenha o intervalo curto (0,05s a 0,15s): com muitos itens, a última linha demora demais. 

@keyframes subir {
  from { opacity: 0; transform: translateY(24px); }
  to   { opacity: 1; transform: translateY(0); }
}

.cascata li {
  opacity: 0;
  animation: subir 0.5s ease forwards;
}

.cascata li:nth-child(1) { animation-delay: 0.10s; }
.cascata li:nth-child(2) { animation-delay: 0.25s; }
.cascata li:nth-child(3) { animation-delay: 0.40s; }
.cascata li:nth-child(4) { animation-delay: 0.55s; }

4. Acessibilidade — prefers-reduced-motion

Para que serve

Para que serve: desligar ou reduzir as animações para quem pediu isso no sistema operacional. Movimento na tela provoca enjoo, tontura e dor de cabeça em pessoas com distúrbios vestibulares ou sensibilidade a movimento — e muita gente simplesmente prefere interfaces paradas.

Quando usar: sempre. É uma única media query no fim do CSS e deveria estar em todo projeto que tenha animação. No macOS a opção fica em Ajustes do Sistema → Acessibilidade → Tela → "Reduzir movimento"; no Windows, em Configurações → Acessibilidade → Efeitos visuais. 

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }

  /* cuidado: o que começa com opacity: 0 precisa continuar visível */
  .fade-in,
  .slide-in,
  .cascata li { opacity: 1; }
}

A armadilha mais comum: zerar as animações e esquecer que o elemento tinha opacity: 0 como estado inicial. Sem a correção acima, o conteúdo some de vez para quem ativou a preferência.
